## Описание

NetBackup отслеживает одну или несколько папок на предмет изменений файлов и автоматически копирует их в папку назначения с сохранением иерархии директорий. При старте выполняется полная начальная синхронизация, после чего запускается мониторинг в реальном времени через `ReadDirectoryChangesW`.

Основные возможности:

- Мониторинг нескольких папок одновременно
- Начальная полная синхронизация при каждом запуске
- Версионирование изменённых файлов (настраиваемое количество версий)
- Фильтрация по расширению файлов
- Загрузка файлов на Google Drive через OAuth2
- Журнал ошибок с возможностью экспорта в TXT и CSV
- Повторная попытка для неудавшихся операций
- Иконка в системном трее
- Сохранение настроек между сессиями

## Архитектура

```
MainWindow.cpp
    |
    |-- Watcher (×N)          наблюдение за папками
    |       |
    |       v
    |-- BackupQueue            очередь копирования (worker thread)
    |       |
    |       |-- FileUtils      копирование, версионирование, пути
    |       |-- Logger         запись событий
    |       |-- GoogleDriveUploader (опционально)
    |               |
    |               |-- GoogleDriveUploadQueue  (worker thread)
    |               |-- GoogleAuth              OAuth2
    |
    |-- Config                 чтение/запись настроек
```

**Потоки:**

| Поток | Назначение |
|---|---|
| Главный (UI) | Обработка сообщений Windows, обновление интерфейса |
| Watcher::Loop (×N) | `ReadDirectoryChangesW` для каждой папки слежки |
| Watcher::DebounceLoop (×N) | Схлопывание дублирующихся событий (2 сек debounce) |
| BackupQueue::WorkerLoop | Последовательное копирование файлов из очереди |
| FullSync thread | Начальное рекурсивное сканирование при старте |
| GoogleDriveUploadQueue::WorkerLoop | Последовательная загрузка на Google Drive |

## Сборка

### Требования

- Windows 10 или новее
- Visual Studio 2019 или новее с компонентом "Desktop development with C++"
- CMake 3.16+
- vcpkg (опционально, для Google Drive)

### Сборка без Google Drive

```bat
git clone <repository>
cd NetBackup
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
```

Исполняемый файл будет создан по пути `build/bin/Release/NetBackup.exe`.

## Использование

### Первый запуск

1. Запустить `NetBackup.exe`
2. Нажать **"+ Добавить папку"** — выбрать одну или несколько папок для слежки
3. Нажать **"Выбрать..."** рядом с полем "Бэкап" — выбрать папку назначения
4. Нажать **"Старт"**

При нажатии "Старт" выполняется начальная полная синхронизация всех файлов. После её завершения запускается мониторинг в реальном времени.

### Ограничения при выборе папок

- Папка слежки и папка бэкапа не могут совпадать
- Папка бэкапа не может находиться внутри папки слежки (и наоборот)
- Нельзя указывать корень диска (`C:\`) или защищённые системные папки

### Системный трей

Приложение сворачивается в системный трей. Правый клик по иконке открывает меню с командами "Запустить бэкап", "Остановить бэкап" и "Выход". Повторное открытие главного окна — двойной клик по иконке или пункт "Показать окно".

### Журнал ошибок

Кнопка **"Ошибки"** открывает окно с перечнем неудавшихся операций. Для каждой ошибки доступна повторная попытка (кнопка "Повторить"). Журнал экспортируется в TXT или CSV.

## Конфигурация

Настройки хранятся в файле:

```
%APPDATA%\NetBackup\netbackup.cfg
```

Формат файла — текстовый, `ключ=значение`, по одному на строку. Строки начинающиеся с `#` — комментарии.

### Параметры

| Ключ | Описание | Пример |
|---|---|---|
| `watchPath_0`, `watchPath_1`, ... | Пути папок слежки | `watchPath_0=C:\Projects` |
| `destPath` | Папка назначения для бэкапа | `destPath=D:\Backup` |
| `maxVersions` | Максимальное количество версий файла (по умолчанию 5) | `maxVersions=10` |
| `versionedExtensions` | Расширения файлов для версионирования (через запятую) | `versionedExtensions=.docx,.txt,.cpp` |
| `ignoreExt_0`, `ignoreExt_1`, ... | Расширения файлов, которые не копируются | `ignoreExt_0=.tmp` |
| `google_refresh_token` | OAuth2 refresh token Google (задаётся автоматически) | — |

Редактировать файл можно вручную. Изменения применяются при следующем запуске приложения.

## Версионирование файлов

При перезаписи файла в папке бэкапа предыдущая версия сохраняется в директорию `.versions` внутри папки бэкапа. Структура:

```
<destPath>/
├── project/
│   └── main.cpp              текущая версия
└── .versions/
    └── project/
        └── main.cpp/
            ├── main_2025-01-15_10-30-00.cpp
            ├── main_2025-01-15_14-22-11.cpp
            └── main_2025-01-16_09-05-47.cpp
```

Версионированию подлежат только файлы с расширениями из списка `versionedExtensions`. По умолчанию это:

```
.docx .xlsx .txt .pdf .cpp .h .hpp .c .cc .cs .java .py .js .xml .json .md
```

Когда количество версий превышает `maxVersions`, самые старые версии автоматически удаляются.

## Google Drive

### Настройка

1. Создать проект в [Google Cloud Console](https://console.cloud.google.com/)
2. Включить Google Drive API
3. Создать OAuth 2.0 Client ID типа "Desktop app"
4. Скачать `client_id` и `client_secret`
5. Прописать их в `MainWindow.cpp` в вызове `GoogleAuth::Initialize()`

### Авторизация

Нажать кнопку **"Гугл"** в главном окне. Откроется браузер с формой авторизации Google. После успешного входа `refresh_token` сохраняется в конфиге автоматически — повторная авторизация при следующих запусках не требуется.

#### **Процесс получения доступа**:
1. Запросите учётные данные OAuth 2.0 у администратора
2. Внесите полученные `client_id` и `client_secret` в конфигурационный файл
3. Выполните авторизацию через интерфейс приложения

---

### Включение загрузки

После авторизации стала активна кнопка **"Облако"**. При её нажатии все последующие скопированные файлы также загружаются на Google Drive. Загрузки выполняются асинхронно в отдельной очереди, не блокируя локальное копирование.

## Логирование

Лог-файл создаётся по пути:

```
%APPDATA%\NetBackup\netbackup.log
```

Формат записей:

```
2025-01-15 14:22:11 - [INFO] Скопирован: C:\Projects\main.cpp (4.2 KB)
2025-01-15 14:22:15 - [ERROR] Ошибка копирования: C:\Projects\locked.docx — Access denied
2025-01-15 14:22:20 - [INFO] [Google Drive] Загружен: C:\Projects\main.cpp
```

Уровни: `[INFO]`, `[WARNING]`, `[ERROR]`. Файл открывается в режиме дозаписи (`append`) — история сохраняется между запусками. Logger потокобезопасен, вызовы из любых потоков корректны.

## Тестирование

Тесты находятся в директории `tests/`. Каждый тест — отдельный исполняемый файл, зарегистрированный в CTest.

### Запуск всех тестов

```bat
cd build
ctest -C Debug --output-on-failure
```

### Запуск отдельного теста

```bat
ctest -C Debug --output-on-failure -R FileUtilsTest
ctest -C Debug --output-on-failure -R WatcherTest
ctest -C Debug --output-on-failure -R ConfigTest
ctest -C Debug --output-on-failure -R BackupQueueTest
ctest -C Debug --output-on-failure -R LoggerTest
```

### Описание тестов

**test_fileutils.cpp** — тесты модуля `FileUtils`:
- Конвертация UTF-8 / wstring
- Определение MIME-типа по расширению
- Вычисление относительного пути, включая случай разных дисков
- Определение вложенности директорий
- Форматирование размера файла
- Определение защищённых путей
- Версионирование: `SaveVersion`, `RotateVersions`
- Копирование файла: `CopyToBackup`
- Вычисление CRC32

**test_watcher.cpp** — тесты модуля `Watcher`:
- Запуск и остановка наблюдателя
- Обнаружение создания, изменения, удаления файла
- Рекурсивное наблюдение за подпапками
- Схлопывание дублирующихся событий (debounce)
- Корректная работа с Unicode-путями
- Повторный старт после остановки
- Защита от двойного запуска без остановки

**config_test.cpp** — тесты модуля `Config`:
- Запись и чтение значений
- Перезапись существующего ключа
- Сохранение в файл и загрузка из файла
- Управление списком путей слежки (добавление, удаление, очистка)
- Настройки версионирования и игнорируемых расширений
- Регистронезависимое сравнение расширений
- Корректное дефолтное значение `maxVersions` при пустой строке

**backup_queue_test.cpp** — тесты модуля `BackupQueue`:
- Запуск и остановка очереди
- Реальное копирование файла во временную директорию
- Дедупликация: повторный `Enqueue` одного пути игнорируется
- Обработка нескольких уникальных файлов
- Несуществующий файл попадает в счётчик ошибок
- Несколько корневых путей: правильный `watchRoot` определяется для каждого файла
- Проверка аргументов `ResultCallback`
- Корректная работа при выключенном Google Drive

**test_logger.cpp** — тесты модуля `Logger`:
- Инициализация: файл создаётся при открытии
- Запись нескольких сообщений
- Все уровни логирования (`Info`, `Warning`, `Error`)
- Режим дозаписи: вторая сессия не затирает первую
- Отсутствие краша при вызове без инициализации

### Особенности тестирования Watcher

`Watcher` использует debounce 2000 мс по умолчанию. В тестах значение снижается до 300 мс через `watcher.SetDebounceDelay(300)`. Windows не гарантирует тип события (`Added` vs `Modified`) для файлов в подпапках при рекурсивном мониторинге, поэтому тесты принимают оба варианта.

## Известные ограничения

- Приложение работает только на Windows (так как используется Win32 API и `ReadDirectoryChangesW`)
- Удаление файлов не реплицируется в папку бэкапа — удалённые файлы остаются в бэкапе
- При копировании больших файлов (>2 GB) возможны проблемы с `fs::file_size` на FAT32
- Google Drive API имеет квоты на количество запросов. При большом потоке изменений возможна throttling-ошибка `429`
- Настройки Google Drive (client_id, client_secret) прописаны в исходном коде и должны быть заменены перед сборкой
- Одновременно может работать только один экземпляр приложения (контролируется через именованный мьютекс)
